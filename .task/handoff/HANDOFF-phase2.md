# Phase 2 — стан інтеграції

## Реалізовано

- Дві демонстраційні ролі з серверними сесіями, паролями через env, logout та перевіркою доступу до `/api/**` на бекенді. Це не production IAM.
- Клієнтський чат прив'язує тікет до customer ID із сесії; історія оновлюється кожні 3 секунди. Є owner-check для кнопок retention і позначка scripted gold.
- Inbox на базі потреби схвалення / ескалації та окрема відповідь оператора із записом `human_reply`.
- Autonomy gate з конфігурацією та евристичними пріорами, захисним рішенням за найсуворішим режимом і оцінкою впливу; Python-еталон має відповідні дефолтні правила. Пріори не є виміряною точністю моделі.
- Діагностика резолюцій, причин зупинки та сегментів синтетичної історії.
- Віджет у iframe з попередньої локальної реалізації доступний через `/?embed=1`; потрібен вхід демоклієнта.
- Класифікатор і генератор відповіді мають окремі параметри моделей Gemma 4.

## Залишилось

- P3 H2/Postgres data layer і SQL-запис дій не реалізовано; джерело лишається in-memory JSON.
- P4 reconciliation двох підписок та сценарій T45 не реалізовано.
- Python віддзеркалює значення autonomy gate за замовчуванням, але ще не читає YAML напряму; при зміні налаштувань потрібна синхронізація.
- Пріори не калібровані за результатами live-eval, а захист від галюцинацій і prompt injection не є абсолютним. Звичайний тестовий запуск не перевіряє платний live API.
- Демо-автентифікація використовує сесії в пам'яті; потрібні production IAM, зберігання й аудити перед роботою з реальними даними.
