# Verified cross-rail demonstration

T45 is a synthetic case with one customer, a cancelled App Store subscription and an active web/card subscription. The customer has two explicitly linked subscription IDs, and each payment carries its subscription ID. The context builder routes to the card subscription only when the links, ownership, processor and cardinality match exactly; ambiguous or unlinked records make the request fail with HTTP 409: no money is moved, and the ticket is not escalated automatically (a known gap, to be fixed later). Subscription routing does not infer cross-account identity from a name, email or fingerprint; the card fingerprint is used only to count recent offers across accounts (`identityOffers`).

For any money-moving request on a cross-rail account (`cancel_refund`, `refund`, `duplicate_charge`), the policy never moves money automatically: it cancels the still-active web subscription, provides the App Store instructions and leaves the refund for operator approval, whatever the classifier's confidence. A cancellation on such an account gets the App Store instructions and no retention discount. Once the web subscription is already canceled, a repeated request still waits for approval but no longer repeats the cancel. The card payment is rechecked by the provider; an already disputed card payment escalates without a refund. The original App Store payment is not mutated. Approval checks the reviewed context again, including both linked subscriptions and the selected payment.

This models mock data only. A production connector must independently establish identity, ownership and payment-to-subscription provenance and support concurrent updates and durable idempotency. To exercise T45 in the customer demo, configure `DEFUSE_CUSTOMER_ID=cus_0195` in gold mode and select its scripted suggestion.
